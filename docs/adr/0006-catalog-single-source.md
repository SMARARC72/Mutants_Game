# ADR-006 — Catalog data single-sourced in-repo, seeded to Postgres, bundled to client

**Status:** Accepted (TDD §5.5) · **Phase:** implemented P0

## Context
Species/gear/skills/factions are static design data needed in two places: the DB mirror (server
validation/analytics) and the client bundle (offline, fast). Two hand-maintained copies drift.

## Decision
One in-repo source produces both. Phase 0: `client/catalog/{species,gear,skills,factions}.json`
generated by `tools/gen_catalog.mjs` (species from `docs/creature_registry.csv`; gear/skills from
`tools/balance_constants.json`; factions authored from the Factions doc). `tools/gen_seed.mjs`
emits `supabase/seed.sql` from that same bundle.

## Consequences
- `supabase db reset` seeds 406 species + 6 gear + 12 skills + 9 factions from the bundle.
- 1 registry row (empty `force_primary`) is skipped (NOT NULL + force CHECK), logged in version.json.
